## 1. Summary

During after hours physical access to an unlocked workstation, an attacker connected a USB drive, opened a folder named `TabFlowPro` from it and planted a Chrome extension in the user's profile. The extension was registered directly in Chrome's `Preferences` with a backdated install time, and a companion binary was set to start through a Run key and a scheduled task. The extension steals session cookies from 12 high value domains and sends them, XOR and base64 encoded, to an attacker controlled server every 5 minutes.

The whole sequence, from USB driver install to the Run key, took 630 seconds.

**Assessment: the `Preferences` entry was written directly, with a backdated install time.**

* `location: 1` with `from_webstore: false` is not produced by a regular install on Windows.
* `install_time` is a round value (no seconds, no microseconds). Chrome writes microsecond precision, for example `13420854332874762` (2026-04-16 23:05:32) in the same file.
* The extension's source files predate the incident by four days, consistent with a package prepared in advance.

### 3.6 Extension behavior (`background.js`)

**Obfuscation.** A base64 string array with a rotation function at the top of the file is never referenced (decoy). The real configuration is in `_cfg`, decoded with `atob`:

| Key | Decoded | Use |
| :--- | :--- | :--- |
| `h` | `https://api.tabflow-cdn.net` | C2 host |
| `s` | `/api/v2/sync` | Exfiltration endpoint |
| `r` | `/api/v2/register` | Victim registration |
| `k` | `tf-2025-x-march-key` | `X-Client-Key` header |
| `id` | `tabflow-pro-ext` | `X-Build` header (base64) |
| `iv` | `beacon_interval` | Not used in code |

**Execution flow.**

| Trigger | Action |
| :--- | :--- |
| `onInstalled` | `_register()` to `/api/v2/register`, creates alarms `_sync` (5 min) and `_hb` (1 min) |
| `_sync` alarm | `_beacon()`: cookies + open tabs + user agent to `/api/v2/sync` |
| `_hb` alarm | Writes a heartbeat timestamp to `chrome.storage.local` |
| `onMessage` (`_t === 0x1`) | Forwards data received from the content script to `/api/v2/sync` |
| `storage.onChanged` (`_tabflow_cfg`) | Changes the `_sync` interval remotely |
| Service worker start | Immediate `_beacon()` |

**Encoding.** `_enc()` serializes to JSON, XORs each character with **`0x5a`**, then base64 encodes. Reversible with CyberChef: `From Base64` then `XOR` (key `5a`, hex).

**Cookie theft.** `_getCookies()` keeps cookies flagged `httpOnly` or `secure` whose domain contains one of **12** targets: `google.com`, `gmail.com`, `outlook.com`, `office365.com`, `linkedin.com`, `github.com`, `facebook.com`, `twitter.com`, `yahoo.com`, `amazon.com`, `paypal.com`, `dropbox.com`. `includes()` makes every subdomain match.

## 8. Gaps and open items

* **Staging scripts not analyzed.** The two scripts provided with the case likely show how `Preferences` was written and how persistence was created. Detections for those steps are based on inference until then.
* **`content_script.js` not fully analyzed.** Hex escaped strings (`password`, `username`, `form`, `addEventListener`) indicate form grabbing, sent to the background through `onMessage`.
* **`mshost_service.exe` not analyzed.** No sample in the evidence.
* **Native messaging host registration not checked.** The extension requests `nativeMessaging`, which requires a manifest registered under `HKCU\Software\Google\Chrome\NativeMessagingHosts\`.
* **Real install time of the extension not confirmed.** Explorer shows `Preferences` modified at 23:31, the same minute as the Run key. Needs confirmation from `$MFT` (`$SI` and `$FN`).
* **Scheduled task creation time not recorded.**

## 9. Lessons

* Browser extensions often sit outside endpoint software inventory, yet they run inside every authenticated session.
* `from_webstore: false` plus an `install_time` that does not match file system activity is a strong signal of a hand written extension entry.
* Each artifact alone is easy to explain away. The value is in the sequence: new USB device, extension outside the managed channel, Run key and task pointing to AppData, all inside ten minutes.
